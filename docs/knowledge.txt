# 人工智能基础概念速查

## 一、Transformer 架构

Transformer 是 Google 在 2017 年的论文《Attention Is All You Need》中提出的深度学习架构。
它完全基于注意力机制（Attention），放弃了循环神经网络（RNN）和卷积神经网络（CNN）的结构，
从而支持大规模并行训练。

Transformer 是 BERT、GPT 等主流大语言模型的基础架构。核心组件包括：

- **自注意力机制（Self-Attention）**：让序列中每个位置都能直接关注其他所有位置，
  计算它们之间的相关性权重，从而捕捉长距离依赖。
- **多头注意力（Multi-Head Attention）**：并行运行多组注意力计算，
  让模型从不同表示子空间捕捉不同类型的关联。
- **位置编码（Positional Encoding）**：因为注意力本身不包含顺序信息，
  需要额外注入位置信息来表示词序。
- **前馈网络（Feed-Forward Network）**：每个位置独立经过的两层全连接网络。

## 二、RAG 检索增强生成

RAG 是 Retrieval-Augmented Generation 的缩写，即检索增强生成。
它先从外部知识库检索相关信息，再把检索结果作为上下文交给大语言模型，辅助其生成更准确的回答。

RAG 主要解决三类问题：

1. **知识时效性差**：大模型的训练数据有截止时间，无法获取最新信息。
2. **无法访问私有数据**：企业内部文档、个人资料等不在模型的训练语料中。
3. **容易产生幻觉**：模型在缺乏依据时会编造看似合理的内容。

需要明确的是，RAG 能降低「知识缺失导致的幻觉」，
但无法解决错误召回、错误理解以及无证据推断这几类问题。

### RAG 的完整流程

离线阶段：文档 → 清洗 → 切块 → 向量化（Embedding） → 存入向量库。

在线阶段：用户提问 → 查询改写 → 召回 → 重排（Rerank） → 构造上下文 → 大模型生成 → 引用验证。

### 切块策略

切块（Chunking）不是简单地按固定字数切分，需要考虑文档结构、任务类型和模型的上下文预算。
常见方法包括：固定长度切块、按段落或标题切块、递归字符切块、语义切块，以及父子块检索。

父子块是一种实用的技巧：用小切块做向量检索以保证精度，命中后返回其所属的大块作为上下文，
从而兼顾召回精度与上下文完整性。

### 向量检索与关键词检索

向量检索擅长捕捉语义相似，但对产品编号、人名、错误码这类精确词不够稳定。
BM25 等关键词检索擅长精确匹配，但对同义表达不敏感。
因此实际系统常采用混合检索：向量召回 + BM25 召回，融合结果后交给重排模型精排。

### 重排（Rerank）

召回阶段追求的是召回率（Recall），即尽量不漏掉相关内容；重排阶段追求的是精确率（Precision），
即把真正相关的内容排到最前面。典型流程是：召回 Top 50 → 重排器精排 → 取 Top 5 交给大模型。

## 三、Agent 智能体

Agent 是大模型驱动的智能系统，能够感知环境、做出决策、执行行动。
它不只是被动地一问一答，而是接收目标、分析当前状态、选择并调用外部工具、
获取环境反馈、根据反馈继续推理，直到完成任务或触发终止条件。

一个完整的 Agent 通常包含这些组成：

```
Agent = Model + Instructions + Tools + State + Control Loop + Memory + Guardrails + Evaluation
```

### ReAct 循环

ReAct 是 Reasoning and Acting 的缩写，其核心循环是：

- **Thought（思考）**：分析当前状态，判断是否需要调用工具、调用哪个工具。
- **Action（行动）**：输出工具名称和参数。
- **Observation（观察）**：获取工具返回的结果，喂回模型继续推理。

循环以上三步，直到模型输出最终答案或触发终止条件。

### Function Calling 原理

Function Calling 并不是让模型直接执行代码。其标准流程是：

1. 应用把工具的名称、描述和参数 JSON Schema 传给模型。
2. 模型返回它想调用的工具名和参数。
3. **应用负责校验参数**。
4. **应用负责执行真实函数**。
5. 应用把结果连同 tool_call_id 返回给模型。
6. 模型生成最终回答，或继续调用下一个工具。

关键点在于：**模型只提出调用请求，应用掌握真正的执行权。**

### 常见的工具调用失败原因

- 工具描述模糊 → 在描述中补充「什么时候该调用、什么时候不该调用」以及反例。
- 参数格式错误 → 用 JSON Schema / Pydantic 做校验，并把错误原因返回给模型。
- 选错工具 → 缩小工具集合，或增加一层路由分类。
- 重复调用 → 对「工具名 + 参数」生成指纹，检测到重复即中断。
- 执行超时 → 设置超时、重试、熔断与降级策略。

### Agent 与 Workflow 的区别

Workflow 由开发者预先定义流程结构，模型只在部分节点做决策，稳定性高。
Agent 则让模型自主规划路径，灵活但不确定性更强。

选择原则是：流程越固定、风险越高，越应该用 Workflow；任务越开放、探索性越强，越适合用 Agent。
能用普通代码或状态机明确实现的部分，应优先确定性实现。

## 四、上下文工程

上下文工程关注的是「模型在推理时能看到的一切」：系统指令、工具返回、检索到的文档、
记忆以及消息历史。目标是用最小的高信噪比 token 集合，稳定地得到期望结果。

它把提示词工程从「系统提示词」扩展到了「整个 token 流」。

### 为什么上下文越长，模型反而不稳定

注意力会被稀释，噪声占比升高，且指令在上下文中的位置会影响其权重。
因此正确的方向不是「尽可能多塞」，而是「精选」。

### 上下文窗口满了怎么办

- 保留系统指令与最近若干轮对话
- 对较早的对话做摘要压缩
- 按相关性检索历史，而不是全部保留
- 工具返回只保留关键字段
- 超大结果放到外部存储，按需读取
- 关键业务状态用结构化的 state 保存，而不是依赖对话文本推断

### 记忆的分层

- **短期记忆**：当前会话的消息、当前任务步骤、已收集的参数。
- **长期记忆**：跨会话的用户偏好、历史任务、实体关系。
- **工作记忆**：当前任务的计划、已完成与待处理步骤、失败原因、预算使用情况。

## 五、Prompt 注入与安全

提示词注入分两类。直接注入是用户输入里包含「忽略以上指令」之类的内容；
间接注入则是 Agent 抓取回来的网页、文档或日志中藏有恶意指令，后者更危险，
因为它不是用户直接说出来的。

工程上的防护手段包括：

- 把外部内容当作不可信数据处理，不作为指令解析
- 在输入、输出和执行动作三个层面设置护栏
- 工具权限最小化，敏感操作放进沙箱
- 高风险操作强制人工审批
- 权限隔离：即使被注入，也因为缺少对应工具而无法造成实际危害
- 完整的审计日志

## 六、评测

Agent 的评测通常分几个维度：

- **效果**：任务成功率、回答准确率、引用正确率、拒答准确率
- **规划**：规划质量、幻觉率
- **工程**：平均延迟、P95 延迟、单次成本、token 消耗
- **安全**：越权拦截率、注入防护命中率

其中「拒答准确率」常被忽略但很重要 —— 它衡量的是系统在知识库中没有答案时，
能否正确地表示不知道，而不是编造内容。这是幻觉的负向指标。

常见评测基准包括 AgentBench、GAIA、SWE-bench、WebArena 等。
